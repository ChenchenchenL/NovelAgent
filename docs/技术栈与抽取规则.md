# 技术栈与抽取规则 v1.0

## 一、技术栈

- 后端：Python 3.11+、FastAPI、SQLAlchemy 2、Alembic、Pydantic。
- 前端：React + Vite，Markdown 编辑器和原文预览。
- 存储：当前创作目录内 SQLite/WAL；正文保存为 Markdown/原文文件。
- 检索：SQLite FTS5、本地可插拔向量索引、SQLite 关系表构成的 KG 投影。
- 传输：REST 命令 + SSE 事件流。
- 本地服务：默认监听 `127.0.0.1`，启动后自动打开浏览器，使用本机会话令牌。
- 目录授权：页面调用 FastAPI 目录选择接口，由后端弹出原生目录对话框；当前目录可写，历史目录只读。
- 模型：OpenAI-compatible 网关；模型配置保存在项目配置，密钥保存在操作系统 Keyring。

## 二、项目和云端边界

云模型默认允许当前项目级上下文，但不自动包含未导入确认的历史目录。实际请求由 `ContextManifest` 记录发送的项目、章节、卷摘要、原文来源和版本。

## 三、抽取对象

首版抽取：人物、影子身份、地点、关键物品、关系事件、剧情事件、时间、伏笔和事实模态。语气指纹、GraphRAG 社区和复杂全局分析属于后续后台任务。

抽取输出必须符合严格 JSON Schema。每个候选至少包含主体、谓词、客体、叙事时间、模态、认知主体、段落范围、字符偏移、来源文本、抽取置信度和实体链接置信度。

## 四、模态与自动确认

支持 `ACTUAL`、`BELIEVED`、`REPORTED`、`REMEMBERED`、`DREAMED`、`HYPOTHETICAL`、`COUNTERFACTUAL`、`METAPHORICAL` 和 `AMBIGUOUS`。

只有以下条件同时满足时才允许低风险自动确认：

1. 来源是作者正文或作者已确认的场景版本。
2. 模态是 `ACTUAL`。
3. 实体通过别名表和规则消歧，模型只是候选补充。
4. 句式明确且来源证据可定位到段落和字符范围。
5. 谓词仅限人物/地点/物品的明确出现、基础属性或位置。

物品转移、关系变化、死亡、剧情事件、身份揭晓、时间跳跃和空间移动必须作者确认。抽取冲突不阻止正文保存，只生成分级报告。

## 五、验收基线

- 正文可在抽取失败或模型不可用时独立保存。
- 唯一物品转移不允许错误来源持有者继续使用。
- 影子身份掉马保留历史来源和知情边界。
- 梦境、传言和隐喻不进入物理事实硬检查。
- 目录未授权时 API 拒绝读写。
- `fsck` 能发现正文文件、SQLite、工作区和派生索引的版本或哈希不一致。
