# NovelAgent 预计开发功能需求 v1.0

> 面向开发团队和实施人员。
> 本文区分当前已实现的骨架、后续待开发功能和分阶段优先级，作为开发排期与验收基线。

## 一、产品目标

NovelAgent 是面向个人作者的本地优先小说创作 Agent。系统需要支持作者手写、AI 辅写、章节和场景管理、正典抽取、人物与剧情连续性检查，以及可恢复的长期创作工作区。

技术基线固定为：

- Python 3.11+、FastAPI、SQLAlchemy 2、Alembic、Pydantic。
- React、Vite、Markdown 编辑器和原文预览。
- 项目目录内 SQLite/WAL，正文保存为 Markdown/原文文件。
- SQLite FTS5、本地可插拔向量索引和关系表 KG 投影。
- REST 命令接口 + SSE 事件流。
- 默认监听 `127.0.0.1`，使用本机会话令牌。
- OpenAI-compatible 模型网关，API Key 保存于操作系统 Keyring。

## 二、当前实现状态

### 2.1 已实现骨架

- 本地启动器、浏览器自动打开、健康检查和本机会话令牌。
- 当前创作目录授权、历史目录只读导入入口。
- SQLite 模型、Alembic 初始迁移和项目初始化。
- Chapter/Scene 基础数据、场景版本、局部补丁和作者采纳。
- 基础候选抽取、事实模态、确认/拒绝/延后仲裁。
- SSE 生成事件接口和基础 React/Vite 工作台。
- 基础 `fsck`、物品守恒规则、模型配置接口和测试骨架。

### 2.2 尚未完成

- 真实云模型 Chat/Embedding 调用；当前生成输出为占位适配器。
- 严格 JSON Schema 模型抽取和模型驱动实体消歧。
- FTS5、向量索引、KG、H-RAG 和 GraphRAG 实际检索链路。
- 完整物品转移、影子身份、空间耗时和剧情影响图 API。
- 完整工作区自动保存、断线恢复和跨介质自愈。
- 完整 Markdown/TXT/JSON/YAML 分批导入和导入进度展示。
- 场景过渡、人物声音、反套话、水字数和伏笔调度检查。

## 三、Phase 1：本地创作闭环（P0）

### P0-01 项目目录和授权

作者可以选择当前创作目录和多个历史目录。当前目录可写，历史目录只读。所有 API 访问必须经过目录白名单校验，未授权目录拒绝读写。

### P0-02 篇章和场景管理

作者可以创建、查看和编辑卷、章节和场景。章节是发布聚合，Scene 是生成、检查和提交的主要单元。场景保存 POV、地点、叙事时间、目标和状态。

### P0-03 版本和局部补丁

场景正文采用不可变版本。局部补丁必须携带基础版本和文本范围；基础版本变化时返回冲突，不得静默覆盖。作者可以只采纳某个段落或场景候选。

### P0-04 持久化工作区

工作区保存手写内容、AI 片段、候选方案、上下文清单、抽取候选和检查报告。应用重启或浏览器断开后能够恢复最近快照。工作区保存不会自动改变正典。

### P0-05 真实模型网关

接入 OpenAI-compatible Chat 和 Embedding 接口。每次调用记录 Endpoint、模型、任务层级、ContextManifest、模板版本、输入输出计量、耗时和结果版本。模型失败不能丢失正文。

### P0-06 结构化逆向抽取

抽取对象包括人物、影子身份、地点、关键物品、关系事件、剧情事件、时间、伏笔和事实模态。输出必须符合固定 JSON Schema，包含实体、谓词、客体、叙事时间、认知主体、来源段落和字符范围、抽取置信度及实体链接置信度。

### P0-07 自动确认和作者仲裁

只有来源为作者正文、模态为 `ACTUAL`、实体已消歧、句式明确、规则通过，且谓词属于人物/地点/物品的明确出现、基础属性或位置时，才允许低风险自动确认。

物品转移、关系变化、死亡、剧情事件、身份揭晓、时间跳跃和空间移动必须作者确认。冲突不阻止正文保存，只生成分级报告。

### P0-08 存量导入

支持 Markdown、TXT、JSON、YAML。导入先保存原文，再按卷、章、场景分批抽取和建立索引。每批拥有检查点，可暂停、重试和断点恢复。导入失败不能回滚已保存原文。

### P0-09 流式生成和恢复

生成采用 REST 命令 + SSE 事件流，支持阶段、片段、失败、取消、完成、断线重连和事件去重。事件序列必须持久化，不能只依赖进程内存。

### P0-10 抽取审核工作台

页面可以展示候选主张、来源证据、模态、置信度和状态，并支持确认、拒绝、延后。作者确认前，候选不得进入高影响正典检查。

### P0-11 跨介质恢复

使用 `CommitJournal` 和 `PendingProjection` 处理 SQLite、正文文件、工作区和派生索引之间的不一致。`fsck` 必须检测缺失文件、哈希冲突、孤立版本、未完成投影和损坏引用。

### P0-12 模型配置和密钥保护

页面可以配置 OpenAI-compatible Endpoint 和模型名称。API Key 只写入操作系统 Keyring，不回显、不写入 SQLite、不进入前端日志。

## 四、Phase 2：长篇连续性和质量控制（P1）

### P1-01 关键物品守恒

新增 `ItemEntity` 和 `ItemEvent`。唯一物品必须显式记录创建、持有、转移、隐藏、遗失、找回和摧毁。唯一物品同一叙事时刻最多有一个有效持有人，错误来源持有者不得继续使用。

### P1-02 影子身份和掉马

新增 `ShadowEntity`、身份假设和 `IdentityRevealEvent`。掉马前不得向当前 POV 泄漏真实身份；掉马后关联历史事件和关系，但保留影子 ID、来源和揭晓前知情边界。

### P1-03 空间和时间连续性

新增地点、路线、交通方式和耗时矩阵。场景衔接时校验人物、物品或事件是否在规定时间内完成移动。特殊移动必须引用作者确认的能力或世界规则，未知路线只报告 `UNKNOWN`。

### P1-04 人物关系和稀疏知情

完善人物阶段、关系事件、关系状态、核心秘密和信息差。只跟踪当前场景和核心秘密相关的知情关系，不维护所有角色对所有事实的全量矩阵。

### P1-05 剧情线和伏笔调度

完善 `PlotThread`、`PlotEvent` 和伏笔生命周期。伏笔保存目标章节区间、触发条件、可见范围、优先级和回收状态。生成时只加载当前窗口内的伏笔，揭秘时通过显式锚点和依赖图反查 setup。

### P1-06 Impact Graph

影响图覆盖 SourceSpan、Claim、人物/物品/关系事件、SceneRevision、ChapterOutput、摘要和索引切片。上游修改只沿实际依赖传播，拼写和不改变语义的润色不得导致全书级失效。

### P1-07 FTS、向量和 KG

实现专名/原句全文检索、本地向量召回和关系表 KG。KG 支持人物关系、物品流转、秘密传播和伏笔路径查询，并保留时间、模态、来源和版本。

### P1-08 H-RAG 和 ContextPack

H-RAG 作为普通续写主路径：项目/卷摘要 → 剧情线/人物摘要 → ChapterOutput/SceneExitState → Scene/Beat → SourceSpan。ContextPack 记录来源、版本、叙事时间、模态、POV 和 Token 预算。

### P1-09 场景衔接检查

检查相邻场景的时间、地点、人物出入、伤势、持有物、行动、情绪、信息和 POV。作者可以标记 `INTENTIONAL_CUT`，系统不强制补写文学留白。

### P1-10 反水字数和反套话

Beat 必须声明有效推进和停止条件。系统识别同义重复、无推进对话、空泛环境描写、套话和超过停止条件的扩写。对已确认正文只报告，不自动改写。

### P1-11 人物语气指纹

为主要人物维护可演进的 `VoiceFingerprint`，覆盖句式、长短句、敬语、文白比例、口癖、称呼、语气词和感知词。生成后提供对照片段和声音漂移报告。

### P1-12 模型分级路由

T0 执行本地确定性规则；T1 负责抽取和初筛；T2 负责计划和连续性检查；T3 负责创作、复杂改写和全局语义复核。降级必须保留不确定性和调用记录。

## 五、Phase 3：全局智能（P2）

### P2-01 社区摘要

按卷、阵营、剧情线和作者标签生成可追溯社区摘要。摘要记录覆盖节点、边、来源版本、算法版本和未决冲突。

### P2-02 GraphRAG

GraphRAG 仅用于跨卷、多跳关系和全局主题分析，不进入普通段落续写关键路径。社区失效由 Impact Graph 定位，不扫描全书重建。

### P2-03 全书深度回顾

支持全书人物弧、关系网、伏笔兑现率、空间时间线、文风漂移和剧情断裂审计。

### P2-04 反馈驱动质量优化

根据作者的确认、拒绝、延后和忽略记录，降低重复误报、套话误报、人物声音误报和无效连续性告警。

### P2-05 高级模型治理

支持本地模型、云模型和兼容供应商的动态路由，统计成本、Token、延迟、失败率和降级效果，但不得改变正典确认边界。

## 六、非功能需求

- 数据安全：未授权目录拒绝读写；历史目录默认只读；云端只允许当前已打开项目上下文。
- 可恢复性：正文优先于抽取和索引；派生索引损坏后可重建；工作区可从快照恢复。
- 可解释性：每条抽取、冲突、偏离和质量报告都必须带来源证据。
- 可追溯性：正文版本、模型调用、ContextManifest、作者决议和索引版本可关联查询。
- 性能：普通场景续写不依赖 GraphRAG；长任务通过 SSE 返回进度；导入支持后台分批执行。
- 兼容性：项目数据目录可独立备份和迁移，Markdown 正文可脱离 Agent 阅读。

## 七、验收基线

- 物品转移后原持有人无法在已确认状态中继续合法使用该唯一物品。
- 影子身份掉马后历史来源、读者可见范围和角色知情状态仍可追溯。
- 梦境、传言、谎言、回忆和隐喻不直接进入物理事实硬检查。
- 上游局部修改不会默认使全书下游章节失效。
- 作者正文在模型不可用、抽取失败、索引损坏或断电后仍可保存和恢复。
- 未授权目录无法通过 API 或页面访问。
- SSE 断线后不会重复生成已确认事件，也不会丢失任务终态。
- `pytest`、API 集成测试、导入恢复测试、`fsck` 测试和前端构建全部通过。

## 八、优先级与排期原则

先完成 Phase 1 的本地创作闭环和恢复能力，再进入 Phase 2 的长篇连续性。GraphRAG、社区聚类和高级全局分析不得作为第一版可用写作的前置条件。
