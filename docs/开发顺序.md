# NovelAgent 开发顺序 v1.0

> 本文是独立的实施顺序文档，不重复描述完整功能需求。
> 执行原则：先建立可恢复的正典和工作区，再接入模型与抽取，最后增加长篇连续性和全局智能。

## 一、执行规则

1. 每个阶段必须先通过本阶段完成条件，才能进入下一阶段。
2. 正典、版本、工作区和恢复能力优先于模型效果和高级检索。
3. 所有新功能先定义数据边界和失败语义，再实现 API 和页面。
4. 派生索引、摘要和 GraphRAG 不得提前成为正典写入入口。
5. 每次阶段交付必须同时更新迁移、测试、启动说明和架构文档。

## 二、阶段总览

```text
阶段 0：工程基线与目录边界
  -> 阶段 1：正典存储和章节/场景版本
    -> 阶段 2：工作区、局部补丁和作者采纳
      -> 阶段 3：真实模型网关和 SSE 任务
        -> 阶段 4：逆向抽取、模态和作者仲裁
          -> 阶段 5：存量导入和跨介质恢复
            -> 阶段 6：人物/物品/身份/空间连续性
              -> 阶段 7：剧情线、伏笔和 Impact Graph
                -> 阶段 8：FTS、向量、KG 和 H-RAG
                  -> 阶段 9：质量控制和模型分级
                    -> 阶段 10：GraphRAG 和全局智能
```

## 三、阶段 0：工程基线与目录边界

### 开发任务

- 固定 Python/FastAPI、React/Vite、SQLite、SQLAlchemy、Alembic 和测试命令。
- 固定项目目录结构、`.novelagent/` 数据目录和 Markdown 正文目录。
- 实现 `127.0.0.1` 启动器、自动打开浏览器和本机会话令牌。
- 实现当前目录/历史目录白名单，历史目录只读。
- 建立统一配置、日志、错误响应和环境检查。

### 阶段输出

- 一个可以启动并打开 Web 页面的小应用。
- 一个未授权目录无法读写的 API 边界。
- `pyproject.toml`、前端构建、基础测试和启动 README。

### 完成条件

- 新环境可以按 README 启动。
- 未携带会话令牌的写请求返回 401。
- 当前目录可写，历史目录的写请求被拒绝。

### 禁止提前开发

不要在此阶段接入模型、向量库、GraphRAG 或复杂领域校验。

## 四、阶段 1：正典存储和篇章骨架

### 开发任务

- 建立 Project、Volume、Chapter、Scene、SceneRevision 数据模型。
- 建立 Alembic 初始迁移和 SQLite WAL/外键约束。
- 实现章节/场景创建、排序、读取和状态变更 API。
- 实现 Markdown 正文文件与 SQLite 版本记录的对应关系。
- 定义 `ChapterContract`、`SceneEntryContract` 和 `SceneExitState` 的最小结构。

### 阶段输出

- 作者可以创建小说、章节和场景。
- 每个场景都有当前版本、历史版本和来源。
- 章节可以聚合场景，但不承担场景级生成细节。

### 完成条件

- 场景版本不可覆盖。
- 场景和章节重新打开后内容一致。
- SQLite 删除派生索引不影响正文和正典版本。

## 五、阶段 2：工作区、局部补丁和作者采纳

### 开发任务

- 实现 `GenerationWorkspace` 和自动保存快照。
- 实现作者手写保存、AI `TextPatch` 和局部段落采纳。
- 实现基础版本校验和局部三方冲突提示。
- 实现工作区恢复、候选方案保留和撤销链。
- 前端完成篇章树、Markdown 编辑器、原文预览和版本操作。

### 阶段输出

- 作者不依赖 AI 也能完成可靠写作。
- AI 可以只改写/续写选中段落，不需要生成整章。
- 浏览器刷新或服务重启后可以恢复未提交工作区。

### 完成条件

- 无重叠补丁可合并。
- 重叠补丁不静默覆盖。
- 工作区保存不会改变正典或触发影响传播。

## 六、阶段 3：真实模型网关和生成任务

### 开发任务

- 实现 OpenAI-compatible Chat/Embedding 客户端接口。
- 实现 T1/T2/T3 模型配置和任务路由。
- 实现 Keyring 密钥保存和模型配置页面。
- 实现 `GenerationRun`、任务状态、取消和重试。
- 将生成事件持久化，再通过 SSE 发送。
- 记录模型、模板、ContextManifest、计量、耗时和失败原因。

### 阶段输出

- 真实模型可以生成候选段落或场景。
- 模型失败、超时或取消不会丢失工作区。
- SSE 断线后可以继续读取已持久化事件。

### 完成条件

- 生成结果先进入工作区，不能自动进入正典。
- 重复请求不会产生重复任务或重复扣费记录。
- 没有模型配置时仍能使用手写和本地规则功能。

## 七、阶段 4：逆向抽取、模态和作者仲裁

### 开发任务

- 固定 ClaimCandidate JSON Schema。
- 实现段落范围、字符偏移和文本哈希来源定位。
- 实现人物、影子身份、地点、物品、关系事件、剧情事件、时间和伏笔候选抽取。
- 实现 `ACTUAL`、`BELIEVED`、`REPORTED`、`REMEMBERED`、`DREAMED`、`HYPOTHETICAL`、`COUNTERFACTUAL`、`METAPHORICAL`、`AMBIGUOUS` 模态。
- 实现别名表、规则优先的实体消歧和模型候选。
- 实现自动确认、确认、拒绝、延后和分级冲突报告。

### 阶段输出

- 作者手写正文可以被逆向提取为候选结构。
- 梦境、传言、谎言和隐喻不会直接进入物理事实硬检查。
- 低风险明确事实可以自动确认，高风险变化必须作者确认。

### 完成条件

- LLM 抽取不能直接触发硬拦截。
- 抽取失败不影响正文保存。
- 每个结构化候选都能回到原文证据。

## 八、阶段 5：存量导入和跨介质恢复

### 开发任务

- 实现 Markdown、TXT、JSON、YAML 文件发现和编码处理。
- 实现按文件/卷/章/场景的批量导入。
- 建立 `ImportJob`、`ImportCheckpoint`、暂停、重试和失败恢复。
- 实现 `CommitJournal`、`PendingProjection` 和正文文件哈希。
- 实现 `novelagent-fsck`，检查 SQLite、正文文件、快照和派生任务。
- 增加备份、导出和恢复命令。

### 阶段输出

- 几十万字存量作品可以先保存原文，再逐批结构化。
- 单批导入失败不会丢失之前的原文。
- 断电或索引损坏后可以恢复最后完整正典提交。

### 完成条件

- 缺失正文文件可以从 SQLite 恢复。
- 缺失 FTS/向量/KG 数据可以重建。
- 哈希冲突保留两份数据并要求作者决议，不自动覆盖。

## 九、阶段 6：人物、物品、身份和空间连续性

### 开发任务

- 实现 Character/CharacterState 和人物阶段。
- 实现 RelationshipEvent/RelationshipState。
- 实现 NarrativeSecret、InformationGap 和稀疏知情追踪。
- 实现 ItemEntity/ItemEvent 和唯一物品守恒状态机。
- 实现 ShadowEntity、IdentityHypothesis 和 IdentityRevealEvent。
- 实现 LocationEntity、TravelProfile、MovementEvent 和最短耗时校验。

### 阶段输出

- 人物关系、关键物品、马甲身份和地点移动成为可验证状态。
- 掉马前后能保持历史来源和知情边界。
- 非超自然移动不会出现同日跨越不可能距离的硬伤。

### 完成条件

- 错误来源持有者不能继续使用唯一物品。
- 影子身份不会在揭晓前泄漏真实身份。
- 未知距离/时间只生成 `UNKNOWN`，不伪造规则结论。

## 十、阶段 7：剧情线、伏笔和 Impact Graph

### 开发任务

- 实现 PlotThread、PlotEvent 和 Foreshadowing 生命周期。
- 为伏笔增加目标章节区间、触发条件、可见范围和优先级。
- 实现 SceneEntry/Exit 对时间、地点、行动、情绪、信息和 POV 的过渡检查。
- 实现 ImpactNode/ImpactEdge 和实体/事件级依赖传播。
- 实现局部 `LOCALLY_STALE` 和影响报告。

### 阶段输出

- 下一场景读取上一场景的明确退出状态。
- 伏笔按窗口和触发条件调度，不全量进入 Prompt。
- 上游局部修改只影响真正依赖它的下游内容。

### 完成条件

- 拼写和不改变语义的润色不触发剧情级失效。
- 关键状态变化能展示完整依赖路径。
- 作者可以标记 `INTENTIONAL_CUT`，系统不强制补写文学留白。

## 十一、阶段 8：全文、向量、KG 和 H-RAG

### 开发任务

- 建立 FTS5 文本切片、专名和原句检索。
- 建立带版本和来源 ID 的本地向量索引。
- 建立关系表 KG 投影和限深路径查询。
- 实现 H-RAG 层级摘要：项目/卷、剧情线/人物、章节输出、场景/Beat、原文片段。
- 实现 ContextPack、模态过滤、POV 过滤和 Token 预算。
- 让所有派生索引可从正典重建。

### 阶段输出

- 普通续写优先使用相邻场景、章节输出和 H-RAG。
- 人物关系、物品流转和秘密传播支持结构化路径检索。
- 向量或 KG 故障不会影响正典写作。

### 完成条件

- 每个上下文片段都能回溯到项目、版本、模态和来源。
- 旧索引不能伪装为最新正典。
- GraphRAG 不可用时普通续写仍然可用。

## 十二、阶段 9：质量控制和模型分级

### 开发任务

- 实现 Beat 推进和停止条件。
- 实现重复、同义改写、无推进对话、空泛描写和套话检测。
- 实现 `ClicheBlacklist` 和项目级词表。
- 实现 `VoiceFingerprint` 和人物声音漂移报告。
- 实现 T0 规则、T1 抽取、T2 检查、T3 创作的路由和降级。
- 建立质量报告去噪、忽略原因和作者反馈记录。

### 阶段输出

- 系统能够提示 AI 水字数和人物声音同质化。
- 已确认正文只生成报告，不被自动重写。
- 模型降级时保留不确定性，不伪装为高等级结果。

### 完成条件

- 不同体裁可以配置不同套话和描写密度规则。
- 作者接受/拒绝/忽略结果可以被审计。
- 质量检查不会把合法慢节奏自动判为错误。

## 十三、阶段 10：GraphRAG 和全局智能

### 开发任务

- 按卷、阵营、剧情线和作者标签建立逻辑社区。
- 实现社区摘要、节点/边覆盖范围和版本记录。
- 实现按 Impact Graph 增量失效和重建社区。
- 实现跨卷人物关系、伏笔网络、人物弧和剧情断裂审计。
- 增加模型成本、Token、延迟、失败率和降级效果统计。

### 阶段输出

- GraphRAG 只服务跨卷、多跳和全局主题分析。
- 普通段落续写不依赖社区聚类或 GraphRAG。
- 全局分析失败不会阻止本地写作。

### 完成条件

- 社区摘要全部可回溯到正典节点和边。
- 单条关系修改不要求全书社区重建。
- 全局分析结果不会直接改变正典。

## 十四、每阶段统一交付清单

每个阶段完成时必须同时提交：

- 数据模型和 Alembic 迁移。
- 后端 API、错误语义和前端最小操作入口。
- 单元测试、API 集成测试和恢复/失败测试。
- 相关架构与技术决策文档更新。
- README 启动、迁移、测试和回滚说明。
- 一份可重复执行的冒烟脚本或验收命令。

## 十五、严格禁止的开发顺序

- 不得在正典版本和工作区恢复完成前接入 GraphRAG。
- 不得在来源、模态和作者仲裁完成前自动写入人物、关系、物品或剧情正典。
- 不得在 Impact Graph 完成前实现全书级自动失效。
- 不得在 SSE 事件持久化前依赖进程内存保存生成状态。
- 不得在 `fsck` 和备份恢复完成前把向量/KG 当作唯一事实源。
- 不得为了达到目标字数自动扩写已确认正文。

## 十六、最终发布门槛

只有以下条件全部满足，才可称为第一版可用：

1. 作者可以从选择目录开始，完成手写、AI 辅写、局部采纳和章节保存。
2. 正文、场景版本、工作区和生成事件在重启后可恢复。
3. 逆向抽取可解释，模态和作者仲裁边界生效。
4. 物品、身份、空间和场景衔接的高风险矛盾可被发现。
5. 上游修改不会无差别污染全书下游内容。
6. FTS/H-RAG 故障不会丢失正典，GraphRAG 不是运行前置条件。
7. `pytest`、API 集成、导入恢复、`fsck` 和前端构建全部通过。
